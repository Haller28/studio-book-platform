Known constraints — don't re-litigate

  • iPhones cannot auto-install an app.No button, no link. Only Share → Add to Home Screen. Android can do one-tap.
  • Apple rejects one-app-per-client.There can only ever be one Salon Vine app.
  • Apple rejects thin website wrappers.An app needs real functionality — push notifications being the obvious one.
  • Browser code cannot keep secrets.Anything in a page is public. Tokens must be server-side.
  • Netlify Pro $20/mo required for private org repos, wildcard subdomains, extra team members
  • Seat limits must be server-side or they're an honour system

Agreed architecture

Multi-tenant — one Salon Vine app serving every salon, not a site per salon. Fix a bug once and everyone gets it. No provisioning tokens, no site sprawl.

Retires: per-salon provisioning, standalone Studio 17 build.
Keeps: portal.html — bookings, calendar, team board, checkout, stylists, expenses, documents, waitlist, forms, reports. Made salon-aware, not rebuilt.

Billing flow, once Stripe is live

  • Signup takes a card, 30-day trial, nothing charged
  • Trial ends → automatic monthly charge
  • Payment fails → Stripe retries and emails the customer
  • 14-day grace — full access, both founders notified
  • Still unpaid → suspended; site shows a notice, login blocked
  • Payment resolves → instant reactivation
  • Manual override available

Stylist invite flow — build to this

  • Owner adds a stylist — name, email, phone
  • System automatically sends email and/or text
  • Message has a link, username, one-time access
  • They tap it → "Hi Zack, you've been added to Cutters"
  • Page shows how to add to home screen, with a picture
  • They set their own password and are in
Use a one-time link rather than emailing a password. Reuse the free carrier email-to-text approach already built here rather than paying for Twilio.
